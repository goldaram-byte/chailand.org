# Габрилеон · Backend (сервер + база данных)

Серверная часть админ-панели парка «Габрилеон». Превращает демо-панель
(`../index.html`) из статичной витрины в реальную многопользовательскую систему
с базой данных, авторизацией, кассой, лояльностью, фискализацией и эквайрингом.

## Стек

- **Node.js 20+** + **Express** — API
- **PostgreSQL 16** — база данных (драйвер `pg`)
- **JWT** (`jsonwebtoken`) + **bcryptjs** — авторизация и пароли

## Быстрый старт

```bash
cd server
cp .env.example .env          # проверьте DATABASE_URL и JWT_SECRET
npm install
npm run reset                 # схема + демо-данные + ~55 дней истории продаж
npm start                     # http://127.0.0.1:4000
```

Демо-пользователи (после `npm run seed`):

| Логин     | Пароль       | Роль          | Доступ                                  |
|-----------|--------------|---------------|-----------------------------------------|
| `owner`   | `owner123`   | Владелец      | всё (`*`)                               |
| `admin`   | `admin123`   | Администратор | касса, клиенты, CRM, праздники, отчёты  |
| `cashier` | `cashier123` | Кассир        | касса, возвраты, клиенты, воронка       |

> ⚠️ В продакшене смените пароли и `JWT_SECRET`.

## Что реализовано

### Пункт 2 — Авторизация, роли, мультипользовательский режим
- Вход по логину/паролю (`POST /api/auth/login`), JWT, `GET /api/auth/me`.
- Роли `owner / admin / cashier` с набором разрешений; проверка прав на каждом
  маршруте (`requirePerm`). Кассир физически не видит настройки/пользователей (403).
- Управление сотрудниками (`/api/users`) и **журнал действий** (`audit_log`):
  кто и когда вошёл, провёл продажу, оформил возврат, изменил настройки.

### Пункт 3 — Офлайн-касса и синхронизация
- Идемпотентность на уровне БД: каждая продажа несёт `client_uuid` (UNIQUE).
  Повторная отправка того же чека возвращает уже проведённую продажу, а не дубль.
- `POST /api/sync` — приём пачки операций из офлайн-очереди кассы; каждая
  операция обрабатывается независимо, ошибка одной не роняет остальные.
- `GET /api/sync/pull` — свежий каталог и настройки для обновления офлайн-кэша.
- Клиентская часть (IndexedDB outbox + движок синхронизации) подключается к этим
  эндпоинтам — см. задачу по фронтенду.

### Пункт 4 — Фискализация и эквайринг (адаптеры)
- Единый интерфейс + **подключаемые драйверы**:
  - `services/fiscal.js` — эмуляция ККТ/ОФД (54-ФЗ). Реальные драйверы
    Штрих-М/Атол + ОФД включаются после установки кассы и договора **без
    изменения кода кассы**.
  - `services/acquiring.js` — эмуляция терминала. Драйверы Сбербанк/ВТБ
    включаются после договора и подключения POS-терминала.
- Каждая продажа автоматически ставит чек в очередь фискализации (`fiscal_docs`);
  ошибка ОФД не откатывает продажу — чек остаётся со статусом `error` для
  повторной регистрации.
- Настройки эквайринга в БД (`acquiring_config`), режим `emulation | real`.

## Структура

```
server/
  src/
    index.js            — Express-приложение, монтирование роутов, отдача index.html
    env.js              — конфигурация из .env
    db.js               — пул PostgreSQL, помощники q()/q1()/tx()
    schema.sql          — идемпотентная схема БД
    migrate.js          — применение схемы
    seed.js             — демо-данные (пользователи, каталог, клиенты, лиды)
    auth.js             — JWT, bcrypt, права, requireAuth/requirePerm
    util.js             — обёртка обработчиков, запись в аудит-лог
    routes/
      auth.js           — вход, профиль
      catalog.js        — группы, товары/тарифы, услуги, комнаты
      pos.js            — смены, продажи, возвраты
      clients.js        — клиенты, дети, бонусы, дни рождения
      crm.js            — воронка (лиды), задачи, перенос в базу
      bookings.js       — бронирование праздников
      reports.js        — дашборд, топ позиций, разрез по группам
      settings.js       — общие настройки, эквайринг
      users.js          — сотрудники, журнал действий
      sync.js           — офлайн-синхронизация
    services/
      sales.js          — общая логика продаж/возвратов (касса + синхронизация)
      fiscal.js         — фискализация (адаптер)
      acquiring.js      — эквайринг (адаптер)
```

## Ключевые эндпоинты

| Метод | Путь | Право | Назначение |
|-------|------|-------|------------|
| POST | `/api/auth/login` | — | вход |
| GET  | `/api/catalog` | auth | каталог целиком |
| GET  | `/api/catalog/tariff?date=` | auth | билеты по типу дня |
| POST | `/api/pos/shift/open` `/close` | shifts | смена |
| GET/POST | `/api/pos/sales` | pos | список / оформление продажи |
| POST | `/api/pos/returns` | returns | возврат |
| GET/POST | `/api/clients` | clients | база клиентов |
| GET  | `/api/clients/:id` | clients | карточка (дети, история, бонусы) |
| GET  | `/api/clients/birthdays/upcoming` | clients | ближайшие ДР детей |
| GET/POST | `/api/crm/leads` | crm | воронка |
| POST | `/api/crm/leads/:id/convert` | crm | лид → клиент |

| POST | `/api/sync` | pos | офлайн-очередь |

## Активируется после подключения сервера и домена

Готово в коде, включается на боевом сервере с доменом и реквизитами:

- **Реальная фискализация**: договор с ОФД + ККТ (Штрих-М/Атол) → драйвер
  в `services/fiscal.js`.
- **Реальный эквайринг**: договор с банком + POS-терминал (Сбербанк/ВТБ) →
  драйвер в `services/acquiring.js`.
- **Push/SMS-уведомления** клиентам (дни рождения, акции) — нужен домен + внешние
  сервисы (для push обязателен HTTPS-домен).
- **HTTPS + бэкапы БД** — на уровне инфраструктуры домена.
